LabGuardian 论文阅读长笔记 04：从链路预测到可验证的电路图编辑修复

上一篇笔记读了 GNN-ACLP，知道了“端口级电路图 + SEAL 链路预测”可以怎样预测缺失连接。但是继续往前追引用、往后看新工作以后，我发现“下游图推理”至少包含五种不同任务：链路预测、元件补全、图匹配、编辑距离预测和图编辑脚本预测。

它们名字相近，实验指标也经常都出现 AUC、Accuracy 或 GED，但解决的问题并不相同。如果不先分清楚，很容易把“判断一条边是否存在”写成“系统能够修复完整电路”，也容易为了加入 GNN 而替换掉本来更可靠的确定性比较。

这篇是给我自己的阶段性长笔记。我把八篇工作放到同一张路线图中阅读，最后只回答一个问题：

LabGuardian 已经从照片恢复出元件、端子、孔位和网表以后，应该怎样得到可定位、可验证、可解释的接线错误和修复建议？

先记住最终结论

读完这一组论文后，我当前的判断是：

  1. 有教师参考电路时，确定性图差分应继续作为主要判定器。 已知观测图和目标图，且元件身份大多能对应时，没有必要让神经网络重新猜一个已经可以由规则计算的答案。
  2. GNN 最适合处理不确定性，而不是取代确定性。 当视觉阶段给出多个 Hole-ID 候选、端子对应不确定或观测网表残缺时，可以让模型对候选编辑排序，再由电气规则和参考图验证。
  3. 链路预测不等于完整修复。 SEAL 和 GNN-ACLP 主要回答候选边是否应该存在，不能自然覆盖多余连线、极性错误、多故障和整图修复成功率。
  4. 图相似度或标量 GED 也不等于错误定位。 它们能说明“两张图差多少”，却未必告诉我应该改哪根线、哪一个端子和哪个孔位。
  5. 真正适合论文主线的是“可验证图编辑”。 系统输出 AddEdge、DeleteEdge、ReassignEdge、SwapPin、ReversePolarity 等结构化操作；每个操作都绑定元件、端子、Hole-ID、electrical node 和视觉证据，并能被规则重新检查。
  6. 数据划分必须先按基础电路完成，再生成故障。 同一正确电路的不同编辑版本不能被随机分散到训练集和测试集，否则模型可能只是在记忆基础拓扑。
  7. 近期最应该补的是诊断闭环实验，而不是先堆更多 GNN。 先证明 Hole-ID、网表恢复、错误定位和修复建议的准确率，再把学习模型作为不确定场景下的增强实验。

论文一：Circuit Design Completion Using Graph Neural Networks

它解决什么问题

这篇 2023 年论文是 GNN-ACLP 的直接前身。作者定义了一个电路补全问题：从原始网表中删除一个元件及其所有连接，系统需要预测被删除元件的类别和连接位置。

流程分成两阶段：

FEGIN 在 GIN 的图表示上加入 NetLSD 全局图描述符，再进行排序池化和分类。需要注意，FEGIN 负责的是缺失元件类别，连接预测阶段仍然采用 SEAL。

图表示和数据

论文将一个元件视作一个节点，元件之间的连接视作边。这比端口级图简单，却无法区分元件的具体引脚。例如，“MOS 管与电阻相连”没有说明连接的是 Gate、Drain 还是 Source。

数据来自三类网表：LTSpice examples、LTSpice demos 和 KiCad GitHub。实验只保留五种最常见元件类别，还删除了过小、过大或稀有类别样本。链路预测图进一步限制在 5 到 25 个节点。

因此，它证明的是经过明显筛选后的可行性，不是对任意电路元件和任意规模网表的完整覆盖。

主要实验结果

元件类别识别中，FEGIN 的加权 F1 分别为：

数据集 GIN FEGIN
LTSpice examples 92.7 93.1
LTSpice demos 87.9 90.0
KiCad GitHub 66.1 67.4

FEGIN 相比 GIN 有提升，但幅度有限，而且 KiCad 数据的绝对结果明显更低。

链路预测中，论文用 2-hop SEAL，每次从测试图删除一个节点，重复 10 次并报告平均 AUC：

数据集 测试图数量 平均节点数 SEAL AUC
LTSpice examples 217 13.52 74.74
LTSpice demos 25 16.47 61.39
KiCad GitHub 29 11.69 75.09

这些连接结果不算高，尤其 LTSpice demos 的测试图只有 25 张。

对我的启发和限制

启发是：可以把“缺了什么”和“应该接哪里”分成两个阶段，降低单个模型的任务复杂度。

不能照搬的部分是：

  • 只删除一个完整元件，不覆盖多接、错接、错孔和极性错误；
  • 元件级图丢失端子角色；
  • 经过类别与图规模筛选，不能代表开放场景；
  • 只报告候选边 AUC，没有整图修复成功率；
  • 论文提到故障诊断潜力，但没有直接完成或评价故障诊断。

论文二：SEAL——为什么围绕候选边提取局部子图

核心想法

SEAL 是通用链路预测方法，不是电路专用模型。对每个候选节点对 (u, v)，它不直接只看两个节点的向量，而是提取它们周围的 h-hop 包围子图，再把整个局部子图分类为“存在链接”或“不存在链接”。

DRNL 的价值是让模型知道哪些是目标节点，以及其他节点相对两个目标的位置，而不依赖原图中的节点编号。

实验怎样做

原论文在 8 个通用网络数据集上实验，从已有边中取 10% 作为正测试边，再采样相同数量的不存在边作为负测试样本；剩余边用于训练。主要报告 AUC 和 AP，并与 common neighbors、Jaccard、Adamic-Adar、Katz 等启发式方法比较。

论文一般在 1-hop 和 2-hop 间选择。h 增大并不一定更好，因为 3-hop 子图遇到高度节点时可能急剧膨胀，带来内存和采样问题。

对 LabGuardian 最有用的部分

SEAL 提供了一个清晰基线：对每个“端子应该接到哪个 electrical node”的候选，提取局部电路结构并排序。

但数据构造必须改造。通用 SEAL 实验常用正负样本数量相同，而真实电路中不存在的节点对远多于正确连接。如果随机采负样本，很多负例过于简单，模型可能只学会排除明显不合法的组合。

LabGuardian 应该加入困难负样本：

  • 同一面包板附近、几何上很像但电气节点不同的孔位；
  • 元件类型允许连接、但参考图中不应连接的端子；
  • 同一 IC 的相邻引脚；
  • 视觉模型置信度相近的 Hole-ID 候选；
  • 改动后仍满足简单度数规则、但电路功能错误的连接。

同时必须保留 common neighbors、Jaccard、Adamic-Adar 等简单方法。若简单启发式已经足够，复杂模型没有论文价值上的必然优势。

论文三：GNN-ACLP——端口级电路链路预测

相比前一篇进步在哪里

GNN-ACLP 将元件的不同端口拆成节点，保留端口类型，再用 SEAL、DRNL 和 DGCNN 预测缺失连接。这解决了元件级图不能区分具体引脚的问题。

主要结果与不能直接接受的结论

论文在 SpiceNetlist、Image2Net 和 Masala-CHAI 等数据上报告较高的候选边分类结果。五折实验 Accuracy 分别为 94.04%、97.10% 和 96.42%，对应 ROC-AUC 为 0.9866、0.9979 和 0.9959。

但是，这些数字不能写成“完整电路修复率”：

  • 每次只随机删除一个顶点并预测连接；
  • 测试集准确率参与 early stopping，结果可能偏乐观；
  • Accuracy 会受到正负样本比例影响；
  • 没有评价多条编辑同时存在时能否恢复整图；
  • 在更稠密的 AnalogGenie 上，SEAL 超过 48 小时未完成；
  • 模型输出候选链接，不自然覆盖删除错误边和极性修复。

论文四：Graph Matching Networks——两张图一起推理

它与普通图嵌入的区别

普通图嵌入模型先独立编码两张图，再在向量空间计算距离。Graph Matching Networks（GMN）则在每一轮消息传递中加入跨图注意力，让一张图的节点主动寻找另一张图中最相近的节点。

这种机制对“参考图与观测图的局部差异”很有吸引力。若两张图基本匹配，跨图差异向量趋近于零；不匹配节点则在传播中被放大。

实验说明了什么

论文先在随机图上构造不同数量的边替换，用 pair AUC 和 triplet accuracy 评价相似度排序。随后在二进制程序控制流图上训练函数相似度模型：同一函数经不同编译器和优化级别得到的图应相似，不同函数应不相似。

二进制函数数据包含 7940 个函数，每个函数约 8 张控制流图，按函数做 80%/10%/10% 的训练、验证和测试划分。论文的 GMN 在该任务上达到 99.28 pair AUC 和 99.18 triplet accuracy，也优于独立图嵌入和 Siamese 模型。

为什么它不是修复器

GMN 输出的是相似度或排序，不是修改位置和编辑脚本。跨图注意力可以作为对应关系的线索，却不能直接当成具有电气意义的端子匹配真值。

它的计算量还包含所有跨图节点对，单层大约为 O(|V1||V2|)。因此更适合：

  • 从多个参考电路模板中先检索相似候选；
  • 对少量候选图做精排；
  • 在节点身份不明确时辅助建立对应；
  • 作为“学习型图相似度”对比实验。

对于 LabGuardian 当前“教师已指定参考电路”的场景，直接做确定性映射与图差分通常更清楚、更快，也更容易解释。

论文五：Graph Edit Networks——输出图编辑，而不是一个分数

它真正贡献了什么

Graph Edit Networks（GEN）提出一种面向图到图预测的输出层。模型不只输出类别或标量，而是预测一系列局部编辑，包括：

  • 节点插入；
  • 节点删除；
  • 节点属性替换；
  • 边插入；
  • 边删除。

这种输出形式与“修复建议”最接近，因为每一步都可以被人理解和执行。

论文证明：如果训练时知道两张图节点集合之间的映射，就可以构造监督编辑序列；若映射最优，得到的脚本会接近最短图编辑路径。

为什么不能直接把它写成电路修复依据

原论文做的是图动态系统的下一状态预测，实验主要是 edit cycles、degree rules、Game of Life 和树结构等概念验证任务。它没有在电路网表、面包板故障或已知参考电路上评价。

更关键的是，GEN 的训练需要节点映射。对 LabGuardian 来说，真正困难的往往正是：

  • 视觉漏检后，观测图与参考图的元件是否还能一一对应；
  • 两个外观相同的电阻怎样确定身份；
  • IC 旋转后引脚编号是否稳定；
  • 一个端子有多个 Hole-ID 候选时采用哪个映射。

如果这些对应关系已经确定，那么参考图差分本身就能产生编辑脚本，不必再用模型猜。

因此，GEN 对我的主要价值是定义输出接口，而不是直接成为当前主模型。我可以借鉴它的“编辑序列”思路，但编辑类型要改成电路语义：

论文六：GNN-based Hierarchical Annotation——学习与规则怎样分工

方法主线

这篇 TCAD 论文输入 SPICE 网表，输出电路层次结构。作者把结构分为：

功能子块可能有大量拓扑变体，例如 OTA、LNA、Mixer 和 Oscillator，因此用 GNN 做近似子图识别和节点分类；基本结构变化较小，例如差分对和电流镜，因此用模板库、VF2 子图同构和图规则精确识别。

这套分工非常值得记住：

变化多、边界模糊的部分交给学习；结构稳定、可以形式化的部分交给确定性算法。

电路图表示

论文采用“元件节点 + net 节点”的二部多重图，不同边类型表示晶体管 Drain、Gate、Source 和无源器件端口。这比把元件直接互连成普通图更能保留电路端口语义。

数据集包含：

数据集 电路数 总节点数 标签数 特征数
OTA-bias 1026 52346 2 18
RF-data 2597 77918 2、3 或 4 18

训练/验证采用 80%/20% 划分，并做五折交叉验证。最佳 GraphSAGE+ 在 OTA-bias 和 RF-data 上的 F1 分别为 92.31 和 90.11。作者还在未进入训练的 OTA、Receiver 变体，以及更大的手工电路系统上测试。

在 928 节点的 phased array 上，GraphSAGE+ 原始 F1 为 0.87，规则后处理后 F1-p 为 0.98。其他许多测试电路经后处理达到 1.00。推理运行时间为毫秒级。

我应该怎样解读“后处理接近 100%”

这不是“纯 GNN 达到 100%”，而是 GNN 预测后加入了 channel-connected component 等电路规则。论文恰好说明：规则不是模型失败后的临时补丁，而是完整系统的一部分。

同时也要保持谨慎：后处理规则围绕已知模拟 IC 结构设计，测试集数量有限；扩展到新类别仍需要人工整理训练集和模板库。论文结论也承认，新增电路块的主要成本是费力的数据标注。

论文七：Image2Net——怎样评价图像到网表

为什么它与我的上游非常相关

Image2Net 的目标是把模拟电路原理图图片转换成网表。它不是面包板照片，但完整展示了从视觉检测到图结构输出的流程：

作者开放的数据包含 2914 张完整电路图、84195 个总标注、48930 个元件标注，并保留 104 个经过人工核验的图像—网表评估对。覆盖 22 种元件类型和多种交叉样式。

NED 指标

作者将预测网表和真值网表转成异构图，再计算图编辑距离 GED。节点包括元件和 net，边类型表示具体端口。节点或边的插入、删除、替换成本都设为 1。

归一化形式为：

NED 越低越好。表格报告：

方法 Successful Rate 平均 NED
Image2Net 80.77% 0.116

实验正文中出现了“平均 NED 为 0.659”的句子，但同页表格、摘要和结论都写 0.116，且 0.116 与整体比较和分布图一致。因此我把 0.659 视为正文笔误，引用时采用 0.116，并在自己的记录中保留这个核对过程。

NED 能做什么，不能做什么

NED 比只评价元件检测 mAP 更接近最终结构目标，适合 LabGuardian 报告完整网表恢复质量。但它仍不是错误诊断指标：

  • 单位成本把不同电气严重程度的错误等价处理；
  • 只给整体距离，不给修复顺序和具体位置正确率；
  • 精确 GED 一般计算困难，论文为每个样本设置了最长 2 小时计算预算；
  • 104 个核验样本仍然不大；
  • 原理图导线追踪与物理面包板 Hole-ID 映射是不同视觉问题。

所以 NED 可以作为辅助整图指标，但不能取代端子到 Hole-ID、网表边和诊断操作的分项评价。

论文八：KCLNet——把电学先验放进图表示

图表示和物理先验

KCLNet 采用“器件节点 + net 节点”的二部图，边类型表示不同 pin。作者进一步根据从电压源到地的电流方向，将电路图转换成有向无环图，并沿深度异步传播消息。

对比学习目标受到 Kirchhoff 电流定律启发：在不同深度保持流入与流出表示的一致性，同时通过节点遮挡等方式构造电气不一致的负样本。

下游实验

论文评价三个任务：

  • 电路分类；
  • 子电路检测；
  • 图编辑距离预测。

KCLNet 在分类中达到 Acc@1 0.949、F1 0.853；在子电路检测中达到 mAP 0.622、F1 0.753、IoU 0.634。消融实验说明 KCL 目标和异步传播都贡献了结果。

GED 任务则将一对图编码后回归一个标量编辑距离，使用 MAE/MSE 评价。它没有恢复最优编辑路径，也没有输出错误端子位置。

版本状态更新

KCLNet 已正式发表于 AAAI-26，而不应只记作 arXiv 新预印本。正式页面给出的信息为 Proceedings of the AAAI Conference on Artificial Intelligence，40(2)，1355–1363。

为什么不能直接搬到面包板

KCLNet 面向模拟 IC，并依赖 DC 电流方向、已知电压源和地、从电源到地的 DAG 化过程。面包板学生电路可能：

  • 接线错误导致断路或不满足预期方向；
  • 包含交流或动态器件；
  • 缺少可靠的电源/地识别；
  • 视觉阶段本身就不确定；
  • 拓扑很小，训练数据远少于论文数据。

因此，KCLNet 对我最有价值的是三个思想：二部图、端口类型和物理约束负样本。是否采用完整 KCLNet 架构需要单独验证，不能因为名字带 KCL 就默认适合所有面包板任务。

LabGuardian 应采用什么图表示

方案 A：端口节点图

每个元件端子是节点，电气连接是边。优点是直接贴近 GNN-ACLP，候选链接定义简单；缺点是一个 electrical node 中多个端子的共同连接可能需要展开成大量边。

方案 B：元件—电气节点二部多重图

边表示“某元件的某个端子连接到某 electrical node”，边类型保存 terminal type。这个表示更接近 Image2Net、层次标注论文和 KCLNet，也避免把一个多端连接网展开成完全图。

我当前更倾向方案 B：

  • 元件节点保存类别、方向、极性和检测证据；
  • net 节点保存面包板 electrical_node_id；
  • 边类型保存 terminal_id / terminal_type；
  • hole_id 作为观测证据附在边上；
  • 一个端子存在多个 Hole-ID 候选时，保留候选分布而不是立即硬选一个。

我认为最合理的下游系统

确定性模块负责什么

  • 已知元件和端子的匹配；
  • expected edge 与 observed edge 的集合差；
  • VF2 或约束匹配；
  • 面包板孔组连通规则；
  • 端口数量、极性和 IC pin 合法性；
  • 应用候选编辑后是否与参考图一致；
  • 正确电路是否保持“不修改”。

学习模块负责什么

  • 多个 Hole-ID 候选排序；
  • 外观相同元件之间的对应排序；
  • 上游漏检时的候选缺失端子或元件；
  • 多个同样能降低图差异的编辑中，选择更符合局部电路先验的一项；
  • 无参考电路探索场景下的连接合理性评分。

LLM 负责什么

下一阶段实验应该怎样做

实验 1：先做 Oracle 图推理上限

完全绕过视觉，直接使用人工标注的观测网表和参考网表：

评价确定性图差分是否能正确处理漏接、多接、错接、引脚交换、极性错误和多故障。这一步如果不成立，后面加入视觉或 GNN 都没有意义。

实验 2：逐级放开上游误差

至少报告三层：

层级 输入 要回答的问题
Oracle-Graph 真值网表 图诊断逻辑的上限是多少
Oracle-Hole 真值 Hole-ID + 自动网表 electrical node 和网表恢复是否正确
End-to-End 照片全自动输出 实际系统最终能修对多少电路

如果条件允许，再加入真值元件框、真值关键点等中间层。这样能定位性能损失来自检测、Hole-ID、网表恢复还是图推理。

实验 5：指标必须直接对应诊断闭环

候选层指标：

  • Hits@1 / Hits@3 / Hits@5；
  • MRR；
  • 候选编辑 Precision、Recall、F1；
  • 不同错误类型的分类别结果。

位置层指标：

  • terminal 定位准确率；
  • observed hole 准确率；
  • expected electrical node 准确率；
  • 可替代 hole 集合命中率。

整图层指标：

  • Exact Netlist Match；
  • Exact Repair Rate；
  • 应用所有建议后与参考图同构的比例；
  • 多故障全部修复率；
  • 正确电路误报率和误修改率；
  • NED / GED 作为辅助距离指标。

拒绝与不确定性指标：

  • accepted precision；
  • coverage；
  • 风险—覆盖率曲线；
  • 在不同置信度阈值下的错误建议率。

教育反馈指标：

  • 是否指出正确元件；
  • 是否指出正确端子和孔位；
  • 建议是否可执行；
  • 是否引入结构化证据之外的信息；
  • 教师评分和学生有效性评分。

实验 6：分类别报告

至少分为：

  • missing connection；
  • extra connection；
  • wrong electrical node；
  • swapped pins；
  • reversed polarity；
  • missing component；
  • extra component；
  • single fault / multiple faults。

还要按元件类型分开报告，特别关注跳线、IC、极性元件和旋转后容易漏检的类别。一个统一的总体 Accuracy 很容易掩盖最关键的失败模式。

当前论文方向的取舍

近期应该作为主贡献的内容

  1. 面包板端子到 Hole-ID 和 electrical node 的可靠映射；
  2. 从检测结果恢复端口级网表；
  3. 与参考电路的确定性图比较；
  4. 可定位、可执行的结构化图编辑诊断；
  5. 从 Oracle 到端到端的分层实验；
  6. 基于证据的 LLM 教学反馈评价。

可以作为增强或消融的内容

  • SEAL 风格的候选连接排序；
  • GMN 风格的跨图节点对应；
  • KCL/端口类型等物理先验；
  • 不确定条件下的学习型候选编辑重排。

暂时不应成为核心叙事的内容

  • 在只有六种基础电路时训练复杂端到端图编辑网络；
  • 用标量 GED 代替错误定位；
  • 把候选边 AUC 写成完整电路修复率；
  • 为了显得“用了 AI”而替换确定性参考图判定；
  • 只在合成错误上验证，不保留学生真实搭建测试集。

这一组论文暴露出的常见实验陷阱

陷阱 1：训练测试泄漏

同一基础电路的多个编辑版本跨集合出现，或者用测试集 Accuracy 做 early stopping，都会让结果偏乐观。

陷阱 2：负样本过于简单

随机选一个遥远、不可能连接的节点作为负例，模型无需理解电路就能判断。应使用几何接近、端口类型合法但电气错误的困难负样本。

陷阱 3：把局部分类当成整图成功

单条边 Accuracy 很高，不代表所有边同时预测后整张网表正确。必须报告 Exact Repair Rate。

陷阱 4：距离正确但位置错误

模型可能正确预测 GED=1，却不知道是哪条边。教育反馈需要位置级指标。

陷阱 5：后处理贡献被隐藏

如果最终结果依赖规则修正，要分别报告模型原始输出和规则后结果，并做消融，而不能全部归功于 GNN。

陷阱 6：只在正确候选必然存在时评价

真实系统中可能因为元件漏检或 Hole-ID 全错，正确修复根本不在候选集合。需要分别报告 candidate recall 和候选集合内排序表现。

  • [ ] 正确电路必须输出空编辑集；
  • [ ] 不确定时允许拒绝，不强行给错误建议。

实验

  • [ ] 先跑 Oracle-Graph；
  • [ ] 再跑 Oracle-Hole；

LLM 反馈

  • [ ] 只允许读取结构化诊断证据；
  • [ ] 输出中必须包含元件、端子和孔位；
  • [ ] 检查是否错误扩展为未验证的电路解释；
  • [ ] 由教师评价正确性和可执行性；
  • [ ] 由学生评价是否易懂、是否有帮助。

下一轮阅读顺序

如果继续深入，我不会再无序寻找“更多 GNN”，而按当前阻塞点阅读：

  1. 节点对应与图差分：VF2、GED、带属性图匹配、约束匹配；
  2. 图编辑监督：如何从图对生成唯一或等价的最小编辑脚本；
  3. 不确定图推理：候选图、概率图和 selective prediction；
  4. 电路故障数据生成：怎样构造物理合理而不是随机的 hard negatives；
  5. 教育反馈评价：结构化诊断到自然语言反馈的事实一致性和用户研究。

其中优先级最高的不是复现 GEN，而是把 LabGuardian 自己的参考网表差分、错误 taxonomy 和评估协议定下来。它们既是确定性系统的基础，也是将来训练图模型时的标签来源。

最后的阶段判断

这一组论文让我确认：我的下游方向确实可以称为图推理，但最准确的研究对象不是笼统的“用 GNN 识别电路”，而是：

从带视觉不确定性的观测网表出发，与参考电路进行端口级对齐，生成可验证的电路图编辑，并将结构化证据转化为教学反馈。

SEAL 和 GNN-ACLP 提供候选连接学习方法，GMN 提供跨图比较思路，GEN 提供编辑脚本接口，Image2Net 提供网表级距离指标，KCLNet 提供电学先验，层次标注论文则告诉我怎样让 GNN、VF2 和规则各自负责最擅长的部分。

真正属于 LabGuardian 的贡献，不是把这些模型拼成一个排行榜，而是完成这条证据链：

只要这条链路能用分层实验闭环证明，即使学习模型只作为不确定候选排序器，论文也会比单纯比较 YOLO 或 GNN 型号更完整、更有说服力。
